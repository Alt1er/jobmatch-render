# План технічного обслуговування JobMatch

**Обраний підхід:** коригувальне обслуговування на основі зворотного зв'язку користувачів + профілактичне (безпека, залежності, моніторинг).
**Платформа:** Render (Web Service + PostgreSQL, безкоштовний план), код — GitHub, автодеплой з гілки `main`.

## 1. Канали виявлення проблем

| Канал | Що ловить | Де дивитися |
|---|---|---|
| Форма «Зворотний зв'язок» (`/feedback`) | помилки, незручності, ідеї користувачів | Адмін-панель → «Звернення» |
| Журнал помилок (`error_log`) | збої сервера (HTTP 500) | Адмін-панель → «Журнал серверних помилок» |
| `/api/health` + Render Health Check | недоступність сервера або бази | Render → Events; за бажанням UptimeRobot (перевірка кожні 5 хв) |
| GitHub Actions (CI) | регресії після змін | вкладка Actions у репозиторії |
| Dependabot | застарілі/вразливі бібліотеки | Pull requests у репозиторії |

## 2. Час реакції на звернення

| Пріоритет | Приклад | Реакція | Виправлення |
|---|---|---|---|
| Критичний | сайт не відкривається, неможливо увійти | до 4 год | того ж дня |
| Високий | не працює завантаження резюме, підбір | до 1 дня | до 3 днів |
| Звичайний | неточний відсоток, незручний інтерфейс | до 3 днів | у найближчому релізі |
| Низький / ідея | новий фільтр, косметичні правки | до 7 днів | за планом розвитку |

## 3. Процес обробки звернення

1. Звернення надходить зі статусом **Нове**.
2. Адміністратор оцінює його, задає пріоритет і переводить у **В роботі** (з короткою відповіддю).
3. Виправлення робиться в окремій гілці, додається тест, CI має бути зеленим.
4. Злиття в `main` → Render автоматично розгортає нову версію (≈ 3–5 хв).
5. Перевірка `/api/health` і сценарію зі звернення на робочому сайті.
6. Статус **Вирішено** + відповідь користувачу («виправлено у версії X»), запис у `CHANGELOG.md`.

## 4. Регламент

| Періодичність | Дія |
|---|---|
| Постійно (автоматично) | Render Health Check, запис помилок, CI на кожен push |
| Щодня | переглянути нові звернення та журнал помилок (5–10 хв) |
| Щотижня | Dependabot PR, `npm audit`, планування виправлень |
| Щомісяця | резервна копія БД (`pg_dump`), `npm outdated`, перегляд статистики й середньої оцінки |
| Кожні ~30 днів | безкоштовна БД Render має обмежений термін — створити копію й перенести/продовжити |

### Резервна копія бази
```bash
# External Database URL — Render → jobmatch-db → Connections
pg_dump "postgres://…render.com/jobmatch" -Fc -f jobmatch_$(date +%F).dump
# відновлення:
pg_restore -d "postgres://…/jobmatch" --clean jobmatch_2026-11-19.dump
```

## 5. Відомі обмеження (план адаптивного обслуговування)
- Тимчасова файлова система Render: оригінали резюме зникають після перезапуску → перейти на S3-сумісне сховище.
- Сервіс «засинає» після 15 хв простою → платний план або регулярний health-ping.
- Немає e-mail-сповіщень про відповідь на звернення → підключити SMTP / Telegram-бота.
