# JobMatch — веб-платформа інтелектуального зіставлення вакансій і резюме

Повноцінний проєкт: **React** (фронтенд) + **Node.js / Express** (бекенд) + **PostgreSQL** (база даних).

Два типи користувачів:

| Роль | Що може |
|---|---|
| **Кандидат** | реєстрація/вхід, завантаження резюме (**PDF / DOCX**), автоматичне розпізнавання навичок і стажу, підбір вакансій з **відсотком схожості** та поясненням (які навички збіглись, чого бракує), відгук на вакансію, керування резюме (редагування, приховування, видалення), перегляд статусів відгуків |
| **Роботодавець** | реєстрація/вхід з профілем компанії, створення/редагування/зняття вакансій, **рейтинг кандидатів** для кожної вакансії з відсотком збігу, перегляд і завантаження резюме, керування відгуками (нова → переглянута → запрошення / відхилена) |

## Швидкий старт (2 команди)

Потрібно лише **Node.js 18+** ([nodejs.org](https://nodejs.org)). PostgreSQL встановлювати **не потрібно** — справжній PostgreSQL 17 вбудований у проєкт і запускається разом із сервером.

```bash
npm run setup     # встановлює залежності (разом із вбудованою БД) і збирає фронтенд
npm start         # запускає базу, створює таблиці, додає початкові дані та стартує сайт
```

Відкрийте **http://localhost:4000** — один сервер віддає і API (`/api/...`), і React-застосунок.

Що відбувається при першому `npm start`:

1. створюється локальна база PostgreSQL у папці `backend/.pgdata` (UTF-8, порт `54329`);
2. створюються таблиці (`schema.sql`);
3. якщо база порожня — додаються 18 вакансій і тестові акаунти;
4. створюється обліковий запис адміністратора (якщо його ще немає).

Наступні запуски використовують ті самі дані. Зупинити — `Ctrl+C` (база зупиняється разом із сервером).
Щоб почати з чистого аркуша — зупиніть сервер і видаліть папку `backend/.pgdata`.

> Перший `npm run setup` завантажує бінарники PostgreSQL (кілька десятків МБ), тому потрібен інтернет. На Windows для PostgreSQL потрібен стандартний пакет Microsoft Visual C++ Redistributable (зазвичай уже встановлений).

### Власна база даних (необов'язково)

Якщо хочете використовувати свій PostgreSQL (локальний чи хмарний), скопіюйте `backend/.env.example` у `backend/.env` і вкажіть:

```
DATABASE_URL=postgres://користувач:пароль@localhost:5432/назва_бази
AUTO_SEED=true      # додати початкові дані при першому запуску
```

Базу даних треба створити заздалегідь, таблиці створяться самі. Для швидкого PostgreSQL у Docker є `docker-compose.yml`:
`docker compose up -d` (користувач, пароль і база — `jobmatch`, порт 5432; тоді `DATABASE_URL=postgres://jobmatch:jobmatch@localhost:5432/jobmatch`).

Окремі команди (за потреби): `npm run db:init` — створити таблиці, `npm run db:seed` — додати початкові дані.

## Як працює алгоритм зіставлення

Код: `backend/src/services/matcher.js`, `skills.js`, `text.js`.

Підсумковий відсоток складається з чотирьох показників:

```
score = (0.55 · навички + 0.30 · текст + 0.15 · посада) · (0.85 + 0.15 · досвід)
```

| Показник | Вага | Як рахується |
|---|---|---|
| **Навички** | 55 % | частка вимог вакансії, які закриває резюме (словник із 99 навичок з укр/англ варіантами написання) |
| **Схожість тексту** | 30 % | косинусна подібність TF-IDF векторів повного тексту резюме й вакансії (з простим стемінгом укр/англ) |
| **Посада** | 15 % | збіг назви вакансії з назвою/заголовком резюме (без слів «junior», «розробник» тощо) |
| **Досвід** | множник 0.85–1.00 | відповідність стажу мінімальній вимозі вакансії |

Якщо у вакансії немає жодної розпізнаної навички, її вага переходить до тексту (75 %) та посади (25 %).
Інтерфейс показує розбивку за кожним критерієм, збіжні та відсутні навички.

Стаж визначається автоматично (за фразами «3 роки досвіду» та діапазонами дат у розділі досвіду, освіта не враховується) і його можна виправити вручну.

> Алгоритм не залежить від БД та API — його можна замінити на модель embeddings (наприклад, sentence-transformers), змінивши лише `matcher.js`.

### База даних (PostgreSQL)

Таблиці відповідають ER-діаграмі з лабораторної роботи №2: `users`, `companies`, `skills`, `resumes`, `resume_skills`, `vacancies`, `vacancy_skills`, `matches` (кеш обчислених відсотків), `applications`. У версії 1.1 додано `feedback` (звернення користувачів) та `error_log` (журнал помилок), роль `admin`.

## API (скорочено)

Усі маршрути — `/api/...`, авторизація — заголовок `Authorization: Bearer <token>`.

| Метод і шлях | Доступ | Опис |
|---|---|---|
| `POST /auth/register` · `POST /auth/login` · `GET /auth/me` | усі | реєстрація (роль `candidate`/`employer`), вхід, поточний користувач |
| `GET /vacancies` · `GET /vacancies/:id` | усі | каталог вакансій (пошук `q`, `location`, `skill`) |
| `POST /resumes` | кандидат | завантаження PDF/DOCX (`multipart`, поле `file`, необов'язково `title`, `years_experience`, `is_visible`) |
| `GET /resumes` · `PATCH /resumes/:id` · `DELETE /resumes/:id` | кандидат | керування власними резюме |
| `GET /resumes/:id/matches` | кандидат | **підбір вакансій з відсотком** |
| `GET /resumes/:id` · `GET /resumes/:id/file` | власник / роботодавець | перегляд і завантаження резюме (для роботодавця — лише відкриті або тих, хто відгукнувся) |
| `POST /vacancies` · `PUT /vacancies/:id` · `DELETE /vacancies/:id` | роботодавець | керування вакансіями |
| `GET /vacancies/mine` | роботодавець | власні вакансії з кількістю відгуків |
| `GET /vacancies/:id/candidates` | роботодавець | **рейтинг кандидатів з відсотком** |
| `GET /vacancies/:id/applications` | роботодавець | відгуки на вакансію |
| `POST /applications` · `GET /applications/mine` · `DELETE /applications/:id` | кандидат | відгук на вакансію, власні відгуки |
| `PATCH /applications/:id/status` | роботодавець | `new` / `viewed` / `invited` / `rejected` |
| `GET /health` · `GET /meta` | усі | стан сервера й БД, версія, тестові акаунти |
| `POST /feedback` · `GET /feedback/mine` | усі / авторизовані | нове звернення, власні звернення зі статусом і відповіддю |
| `GET /feedback` · `PATCH /feedback/:id` | адміністратор | усі звернення (фільтр `status`, `category`), зміна статусу/пріоритету, відповідь |
| `GET /admin/stats` · `GET /admin/errors` | адміністратор | статистика системи, журнал серверних помилок |

## Безпека та обмеження

- Паролі зберігаються як bcrypt-хеші; сесія — JWT (термін дії `JWT_EXPIRES_IN`). **Перед публікацією змініть `JWT_SECRET`** (у `NODE_ENV=production` сервер без нього не стартує).
- Файли перевіряються за розширенням і «магічними» байтами, розмір — до 5 МБ (`MAX_UPLOAD_MB`).
- Контакти кандидата (e-mail) роботодавець бачить лише після того, як кандидат відгукнувся. Кандидат може приховати резюме від рейтингу.
- Вбудована БД призначена для розробки, презентації та невеликих розгортань; для серйозного продакшену вкажіть власний PostgreSQL через `DATABASE_URL`.
- Скановані PDF без текстового шару не підтримуються (немає OCR) — сервер повідомить про це.
- Словник навичок орієнтований на IT-вакансії; для інших галузей його можна розширити у `backend/src/services/skills.js`.

## Якщо щось не запускається

| Проблема | Що зробити |
|---|---|
| `Вбудований PostgreSQL не запустився` | Запустіть `DEBUG_PG=1 npm start` (PowerShell: `$env:DEBUG_PG=1; npm start`) і подивіться журнал бази |
| Порт 4000 або 54329 зайнятий | Змініть `PORT` / `EMBEDDED_PG_PORT` у `backend/.env` |
| Вікно закрили аварійно, процес `postgres` залишився | Нічого робити не треба — наступний `npm start` підхопить його. Або завершіть процес `postgres` у диспетчері завдань |
| Хочу скинути всі дані | Зупиніть сервер, видаліть `backend/.pgdata` і папку `backend/uploads` (крім `.gitkeep`) |
